## 二、部署步骤（10 分钟）

### 1. 数据库：跑 v4 脚本

Supabase → 左侧 **SQL Editor** → New query → 打开 `supabase-setup-v4.sql` → 全选粘贴 → **Run**。

> 前提：之前已经跑过 `supabase-setup.sql`（v3）。v4 只新增表、加一列、加权限，**不会删数据**，可以重复执行。
>
> 如果你之前已经跑过一次 v4，请**再跑一遍**：这次新增了原子函数 `accept_team_application` 和 Storage 单文件 20MB 限制，重复执行不会报错。

跑完后可以执行这三句自检：

```sql
select count(*) from public.profiles;
select count(*) from public.courses;
select count(*) from public.teams;
```

有数字（哪怕是 0）就说明表建好了。

然后再跑一次 **`seed-courses.sql`**，把 5 门课（C语言、跨文化交流、人工智能通识导论、公共外语、高等数学）插进去：

```sql
-- 跑完自检，应该返回 5
select count(*) from public.courses;
```

### 2. 上传文件到 GitHub（先做一次 2 分钟清理）

把本目录推到 GitHub 即可。注意：

- `functions/api/*.ts` 必须保持这个路径（Cloudflare Pages 会自动识别成 `/api/profile`、`/api/courses`、`/api/teams`、`/api/lostfound`、`/api/stats`）
- `assets/p0.css`、`assets/p0.js` 也要上传
- `seed-courses.sql`、`内容包-5门课.md`、`答辩脚本.md` 是种子内容和比赛材料，建议一起传
- `.backup-*.html` / `.backup-*.sql` 不用传（`.gitignore` 已经排除）

> ⚠️ **重要：`functions/api/` 里的旧备份文件要先处理**
> 目录里现在有 `items.backup-before-auth.ts`、`items.backup-before-admin.ts`、`chat.backup-before-admin.ts`。
> Cloudflare Pages 会把 `functions/` 下的**每个 `.ts` 都当成一个接口**发布，等于多出几个没人维护的旧接口。
> 建议把它们移到项目根目录新建的 `backups/` 文件夹（不要放在 `functions/` 里），或者直接删掉。
> `.gitignore` 已经加了 `*.backup-*.ts`，只要不 commit 就不会被部署。

上传前检查一下：

```bash
git status
```

确认没有把 `*.backup-*` 文件加进去。

### 3. Cloudflare Pages 环境变量

在 **Pages → 你的项目 → Settings → Environment variables** 里确认 / 新增：

| 变量 | 是否必填 | 说明 |
|---|---|---|
| `SUPABASE_SERVICE_ROLE` | **必填** | Supabase → Settings → API → `service_role`，只放服务端，绝不能进前端 |
| `ADMIN_EMAIL` | 建议 | 管理员邮箱（多个用逗号分隔），管理员点认证会自动通过 |
| `CAMPUS_INVITE_CODE` | 选填 | 班级邀请码，默认 `HAOHAI2026`，**上线前改掉** |
| `CAMPUS_EMAIL_DOMAINS` | 选填 | 学校邮箱域名白名单，如 `xxx.edu.cn`，多个用逗号分隔 |
| `OPENROUTER_API_KEY` | 已有 | AI 助手用 |
| `ALLOWED_ORIGIN` | 已有 | AI 接口来源白名单 |

改完环境变量后 **重新部署一次**（Deployments → Retry deployment），函数才会拿到新变量。

### 4. 验证

1. 打开站点 → 点「课程」→ 能看到课程中心（空数据时会提示"还没有课程"）。
2. 登录 → 「我的」→ 「校园认证」→ 输入 `HAOHAI2026`（或你改后的邀请码）→ 显示"校园已认证"。
3. 「课程中心」→「＋ 建课程」→ 建一门课 → 点课程卡片 → 上传资料到这门课 / 写攻略。
4. 「组队广场」→「＋ 发起组队」→ 换第二个账号申请加入 → 队长账号在「我的 → 待处理申请」里通过。
5. 回到旧模块（资料 / 比赛 / 美景）确认没坏；管理后台 `admin.html` 确认还能登录、下架。
6. 「失物招领」→ 发布一条带照片的信息 → 换第二个账号提交线索 → 发布者点「确认」→ 状态变「已找回」。
7. 「数据」→ 能看到访问、下载、AI、课程、组队、失物找回数字（不是全 0）。

## 三、数据表说明（v4）

| 表 | 作用 |
|---|---|
| `profiles` | 昵称、学院、专业、年级、简介、`verified` 认证状态 |
| `courses` | 课程名、老师、学院、学分、学期、考核方式、简介 |
| `course_reviews` | 课程攻略（评分 1–5，一人一课一条，可修改） |
| `teams` | 组队帖（竞赛 / 课程大作业 / 学习搭子），含技能、人数、截止日期 |
| `team_applications` | 入队申请（pending / accepted / rejected） |
| `lost_found` | 失物招领（丢失/捡到、地点、日期、照片、状态） |
| `lost_found_claims` | 认领线索（发布者确认后信息变为已找回） |
| `site_items.course_id` | 原有资料挂到课程上 |

权限规则：

- 所有人可读课程 / 组队 / 攻略；游客不能写
- 建课程、发组队、写攻略、申请入队 → 必须**已认证**
- 只能改 / 删自己发布的内容
- `profiles.verified` 普通用户无权修改（数据库列级授权），只能由 `/api/profile` 用 service_role 写入
- 管理员仍然走 `service_role` 绕过 RLS（原有 `/api/admin` 不变）

## 四、设计上的几个取舍（答辩可以直接讲）

1. **为什么课程是骨架**：资料原来只是"文件名"，没有课程 / 老师 / 学期维度，搜不到、沉淀不了。挂到课程后，资料、攻略、组队、AI 都有了索引。
2. **为什么认证放在最前面**：非本校的人不能发帖，才有"可信校园身份"；这也是通用平台（QQ 群、网盘）给不了的。
3. **为什么组队不做私信**：先用"申请 → 队长通过"的最小闭环，避免一开始就做聊天室；联系方式让用户站内沟通，降低隐私风险。
4. **为什么没有做二手交易**：纠纷和资质风险高，比赛阶段任何做不完的模块都会拉低完成度得分。

## 五、数据量保护（本轮一起加的）

内容变多以后最先出问题的不是数据库，而是**图片内存**和**一次拉全表**。这次加了 5 道保护：

| 保护 | 做了什么 | 效果 |
|---|---|---|
| 照片压缩 | 上传前把图片压到最长边 1600px、JPEG 0.82 | 5MB 原图变 ~300KB，1GB 能存约 3000 张 |
| 懒加载 | 照片列表加 `loading="lazy"` | 只加载屏幕内的图，手机不再一次解码几百张 |
| 上传限制 | 资料 ≤20MB、照片 ≤15MB，前端直接拦；Supabase bucket 设 20MB | 不会因为一个大文件把空间占满 |
| 本地缓存保护 | `localStorage` 只存最近 300 条，并 try/catch | 缓存满也不会误报"云端未连接" |
| 清单上限提示 | `/api/items` 最多返回 1000 条，返回 `truncated` | 数据超过 1000 条时明确提示，不再静默丢内容 |
| 组队人数原子更新 | 新增 SQL 函数 `accept_team_application` | 队长双击/多标签同时通过，人数不会加错或超员 |

如果以后要突破 1000 条：把 `/api/items` 改成 `offset` 分页 + 前端"加载更多"，数据库本身能存几十万条。

## 六、已知限制（P1 再做）

- 管理后台暂时不能管理课程 / 组队（需要时可在 Supabase 后台直接改 `status`）
- 没有站内消息推送；待处理申请显示在「我的」，队长需要主动看
- 认证是邀请码 / 邮箱域名，还没有接学校统一身份（需要校方合作）
- 课程资料没有版本管理和审核队列，靠作者自删 + 管理员下架
- 清单一次最多显示最近 1000 条（已提示，后续可改成分页）
- 失物招领的照片存在 Supabase Storage（和资料共用 1GB 免费额度），照片已做前端压缩
- 数据看板是 60 秒缓存，刚产生的访问可能延迟 1 分钟显示

## 七、给一个人的你：下一步优先级

1. **先灌内容再推广**：用 AI 草稿箱生成"每个学院 5 门核心课的资料包 / 复习提纲"，人工审核后发布，别让评委看到空课程页。
2. **只打透一个学院 / 一个专业**：课程、资料、组队都围绕它做深，答辩时讲"我们先把计算机学院跑通了"，比"全校都能用"可信。
3. **把数据埋点用起来**：现在已有 `visit / download / ai`，建议再加 `course_view / team_apply / team_success / lostfound`，答辩时用真实数字说话。
4. **比赛前准备两个账号**：一个队长、一个申请人，现场演示"发帖 → 申请 → 通过"的 30 秒闭环。
